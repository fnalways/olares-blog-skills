# SVG 组装与可编辑交付

`scripts/compose_svg.py` 只依赖 Python 标准库，将生成的位图、官方矢量 Logo 与独立文本节点组成自包含 SVG。它负责合成，不负责生图、设计判断或自动排版。

## 配置示例

将下列 JSON 保存为 `cover.json`。素材路径相对配置文件解析，也接受绝对路径。将技能中的官方 Logo 复制到输出目录后使用。

```json
{
  "width": 1800,
  "height": 600,
  "title": "How to Choose Model Files for Olares",
  "description": "Model sources on layered paper panels.",
  "background": "#F0F5FA",
  "layers": [
    {"type": "image", "id": "Artwork", "path": "artwork.png", "x": 0, "y": 0, "width": 1800, "height": 600, "fit": "slice"},
    {"type": "svg", "id": "Olares-logo", "path": "olares-logo-black.svg", "x": 80, "y": 70, "width": 190, "height": 44.84},
    {"type": "text", "id": "Article-title", "x": 80, "y": 282, "lines": ["How to Choose", "Model Files for Olares"], "line_height": 101, "font_family": "Poppins", "font_size": 76, "font_weight": 700, "letter_spacing": -2, "fill": "#142331"}
  ]
}
```

```sh
python3 <skill-dir>/scripts/compose_svg.py cover.json cover.svg
```

图层按数组顺序叠放。`image` 支持 PNG、JPEG、WebP，并内嵌原始文件；`fit` 为 `meet`（完整放入）或 `slice`（等比填满并裁切）。`svg` 保留内部矢量并给 ID 加前缀，支持本地简单 SVG；脚本会拒绝外部依赖、脚本和复杂嵌入内容。遇到不支持的官方 SVG 时检查并简化副本，不改原始资产。`text` 的 `y` 是首行基线，后续行由 `line_height` 控制；默认左对齐，`anchor` 可为 `start`、`middle`、`end`。

脚本不自动测量字体或文字溢出；必须实际渲染后检查。字体不内嵌，交付时注明字体及字重，接收方需有对应字体。不要把系统替代字体的渲染结果当成目标字体效果。

## PNG 导出

优先用已有的 SVG 渲染器，例如已安装的 Sharp，或当前环境提供的导出工具。不要为此改变全局依赖。Codex 桌面可用 workspace dependencies 工具查找运行时。

以下示例使用当前 Node 环境中的 `sharp`，或通过 `SHARP_MODULE` 指向已安装的模块：

```js
const sharp = require(process.env.SHARP_MODULE || 'sharp');
sharp(process.argv[2]).png().toFile(process.argv[3]);
```

确认 PNG 的真实尺寸与配置一致，查看整图以及缩略图。用于 Figma 的 SVG 尽量使用基础节点与内嵌图片；不要未经实际导入就承诺分层或字体兼容性完全一致。

## 修改标题

复用原始配置，修改 `title` 和文字图层中的 `lines`，必要时调整字号、行距和坐标。保留插画文件与其他图层。只改标题不触发生图。

建议交付：`cover.svg`、`cover.png`、`cover.json`、源插画、生成提示词。说明文字、标签、矢量 Logo 可分别调整，生成的插画仍为嵌入位图。若另需文字轮廓版，另存文件并保留可编辑原版。

## 真实界面与输入/输出示例

采用真实界面方案时，保存未经修改的截图并记录来源。可在 SVG 中通过嵌套 `svg` 的 `viewBox` 裁出应用标识、关键状态或结果区域；截图仍以内嵌 data URI 保存。当前 `compose_svg.py` 支持整张图片的 meet/slice，不直接支持自定义截图视口；需要局部裁切时，使用项目内的组装脚本，并把裁切坐标保存到配置中。

分开裁切品牌区与内容区时，记录两者均来自同一张真实截图。不要重绘数值、拼接成未发生过的运行状态，或用模型生成的界面替换原始证据。界面截图中的文字是位图，不应宣称可编辑。

工单原句、命令、JSON 等示例适合用独立 SVG 文本层；代码可使用等宽字体，标题仍沿用封面字体。示例属于视觉主体的说明，不另加营销副标题。前景面板不要遮住关键状态和结果；同时检查整图与缩略图。

此方向的交付可用原始截图替代“源插画”。若没有使用生图，省略生成提示词；纯色或纯图形背景可直接使用原生 SVG。

## 纯图形背景与标题

图形背景可作为独立矢量组，与 Olares 标识、标题分别编辑。无需把几何形状栅格化；按项目需要记录生成参数或组装脚本。只有需要继续编辑背景时再额外交付无文字背景，不默认建立跨文章套版模板。

标题可在同一行使用不同字重；使用相邻 `tspan` 时留意空白折叠，必要时显式保留空格并实际渲染检查。宽标题应连同后方图形一起检查阅读对比，不能只验证文字是否在画布内。

## 磨砂玻璃、光晕与效果分层

目标是让用户可以改效果，而不是只看到效果。建议按实际使用情况命名为 Background、Artwork、Title backing、Glow、Title、Olares logo、Labels；根据设计决定前后顺序，无需创建空图层。

| 效果 | Figma 原生交付 | SVG 交付与边界 |
| --- | --- | --- |
| 标题下的磨砂玻璃 | 独立面板形状，半透明填充，背景模糊；按需要加轻描边或高光。保留形状、填充透明度和模糊参数 | 普通 SVG 没有可依赖的跨渲染器背景模糊方案。可用与背景同坐标的素材副本，先模糊再裁到面板区域，并叠加半透明填充来近似；背景改变时需要同步副本，不等于实时背景模糊 |
| 标题后的柔和光晕 | 独立椭圆或自由形状，渐变/颜色填充，调整透明度，可加图层模糊 | 优先独立径向渐变形状；必要时使用高斯模糊并扩大滤镜区域避免硬切边。Figma 导入后需要实际核对是否保留原生效果 |
| 标题阴影或微弱外发光 | 作为文本节点的独立效果保留，不把文字变图片 | 独立效果组或滤镜可用于渲染，但跨工具编辑能力不作保证；始终保留原始文本 |

磨砂模糊的是面板背后的内容；给半透明白色矩形自身加图层模糊，只会让矩形边缘变软，不能称为同一种效果。光晕则可以通过模糊自身的形状产生。文字始终放在所需的衬底与光晕之上，保持清晰。

当前 `compose_svg.py` 是基础图片/矢量/文字组装器，没有磨砂或光晕的专用配置，也不负责 Figma 效果转换。复杂效果可在项目组装代码中显式实现，或按用户授权在 Figma 中用原生图层完成；不要仅添加说明就声称脚本已支持这些能力。操作 Figma 时读取适用的 Figma 技能和当前 API 文档。

交付包含效果的设计时，说明哪些是原生可编辑效果，哪些是 SVG 近似或位图。检查效果开关、透明度、模糊、图层顺序与标题编辑；至少查看一次最终渲染，必要时同时看关闭效果后的画面，确认效果在帮助阅读而非遮盖构图问题。
